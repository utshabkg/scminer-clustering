\section{Problem and Method}\label{sec:method}
This section states the selection problem, describes the two clustering pipelines we
compare, and defines the label-free rules that choose a final partition. The rules are
the part that differs from the published benchmark, so they are given in full.

\subsection{Setup and notation}
The input is a matrix $X \in \mathbb{R}^{n \times g}$ after preprocessing, where $n$ is
the number of cells and $g$ the number of genes. Row $x_i$ is one cell. A clustering
method is a function that takes $X$ and one setting $s$ and returns a partition
$P_s$ of the $n$ cells into clusters, with $|P_s|$ the number of clusters it produced.
For MICA in small-data mode the setting is the number of clusters $k \in \{2,\dots,20\}$,
and $|P_s| = k$ by construction. For Leiden and for MICA in graph mode the setting is a
resolution $r > 0$, and $|P_s|$ is whatever the community detection returns, rising with $r$.
Reference labels $y \in \{1,\dots,c\}^n$ exist for every dataset but are used only for
scoring, never for selection.

\subsection{MICA, the method under test}
MICA is the clustering module of scMINER \cite{pan2025scminer}. We run the authors'
released implementation at commit \texttt{54fae81}, not a reimplementation. It scores a
pair of cells by binned mutual information. Each cell is discretised into
$b = \lfloor g^{1/3} \rfloor$ equal-width bins between that cell's own minimum and maximum
value, giving a discrete variable $C_i$ per cell, and the distance is
\begin{equation}
D(i,j) \;=\; 1 - \frac{I(C_i; C_j)}{H(C_i, C_j)},
\label{eq:mi}
\end{equation}
where $I$ is mutual information and $H$ the joint entropy, both in nats, estimated from
the joint histogram of the two cells' bin codes across the $g$ genes. Dividing by the
joint entropy puts $D$ in $[0,1]$ and makes it a metric \cite{vinh2010information}.

MICA then takes one of two paths, switching at 5,000 cells. Below that it runs
\emph{small-data mode}: classical multidimensional scaling of the full distance matrix to
19 dimensions, then $k$-means. Above it runs \emph{graph mode}: an 80 nearest neighbour
graph under $D$ built with HNSW \cite{malkov2020efficient}, a node2vec embedding into 20
dimensions, and Louvain over a resolution grid. Nine of our ten datasets fall in
small-data mode and PBMC14K in graph mode, which is why the setting is $k$ for most
results and a resolution for PBMC14K.

Our own implementation of Eq.~\ref{eq:mi} agrees with the authors' code to within
$10^{-6}$, and we use it only where the released code offers no entry point, namely for
the subsample distances in Section~\ref{sec:design}.

\subsection{The baseline}
The baseline is the pipeline most practitioners run: principal component analysis to 50
components, a 15 nearest neighbour graph on those components, and Leiden community
detection \cite{traag2019louvain} through Scanpy. Its setting is the resolution.

\subsection{The selection problem}
The published benchmark fixes the setting with the labels. Every method is either given
the true number of types $c$, or has its resolution swept and keeps only runs with
$|P_s| = c$, breaking remaining ties by the highest agreement with $y$. That design
answers a well-posed question, which is how the clustering machinery compares when the
number of clusters is held at the truth. It cannot answer what a user obtains on data
whose cell types are unknown, because both inputs to the selection are then unavailable.

We therefore require a \emph{selection rule}: a function that maps the candidate set
$\{P_s\}$ to one chosen setting $\hat{s}$ using $X$ alone. The same rule is applied to
both methods, and only afterwards is $P_{\hat{s}}$ scored against $y$.

\subsection{The selection rules}
\textbf{Default.} Use the setting the software ships with: resolution 1.0 for Scanpy's
Leiden, and 1.822 for MICA, which we score at 1.8, the nearest point on its own grid.
This is what a user gets by running the tool unmodified. MICA's value is hard-coded in
its source with no stated derivation, so if it was chosen against these same benchmark
datasets it carries label information that Scanpy's default does not. We treat it as a
weak rule for that reason.

\textbf{Silhouette.} Keep the setting with the highest mean silhouette. In Assignment 2
this was computed in each method's own embedding, which confounds the partition with the
space. Here it is computed for both methods in one shared space, the 50 principal
components, so that only the partitions differ.

\textbf{Stability.} Rerun the method on $B$ random subsamples of $80\%$ of the cells and
prefer settings whose clusters survive resampling. We follow chooseR
\cite{pattersoncross2021chooser}. For setting $s$, let $f_{ij}$ be the fraction of
subsamples containing both cells $i$ and $j$ in which they were placed in the same
cluster. Treating $1 - f_{ij}$ as a distance, compute each cell's silhouette with respect
to the full-data partition $P_s$, average within each cluster, and take the median across
clusters as the score $\sigma_s$. A percentile bootstrap over cells gives an interval for
$\sigma_s$. The threshold is the largest lower bound over all settings, and chooseR then
keeps the setting with the most clusters whose score clears it.

That last step encodes a preference for fine partitions, and its authors note it leans
toward overclustering. Because reproducibility by itself says nothing about whether a
split is real, we also report the plain maximum, $\hat{s} = \arg\max_s \sigma_s$ with ties
going to fewer clusters. The two readings share all the computation and bracket how much
the outcome depends on that preference rather than on the data. We call them
\emph{finest stable} and \emph{most stable}.

\subsection{An exactness property that makes the stability rule affordable}
The stability rule needs the method rerun on every subsample, and for MICA each rerun
would need a new distance matrix, which is the dominant cost. It does not. In
Eq.~\ref{eq:mi} the bin edges for cell $i$ come from that cell's own minimum and maximum,
and the histogram is taken over genes. No term depends on any third cell. So for any
subset $S$ of cells, the distance matrix computed on $S$ equals the corresponding
submatrix of the distance matrix computed on all cells. We compute the full matrix once
per dataset and take submatrices, which is exact rather than an approximation. The
property is pinned by a test that recomputes the distance on a random half of a dataset
and asserts equality with the submatrix, in both of MICA's modes. Every step after the
distance, the multidimensional scaling included, is redone on each subsample.
